# 隐私、合规与品牌边界（privacy-and-safety.md）

## 声明

本工作台（mc-life-desk 麦麦人生工作台）是**麦当劳程序员创意开发大赛参赛作品**，不是麦当劳官方产品。用户首次使用时应告知此声明。

## 凭证安全

- 不记录、不提交、不展示真实 MCP Token、密码、手机号或账号凭证
- `mcp-config.example.json` 只能使用环境变量或占位符（`YOUR_MCP_TOKEN`），不得包含真实 Token
- 用户在对话中不小心粘贴了 Token → 提醒其尽快在麦当劳开放平台重置，且不把 Token 写入任何文件或回复

## 数据边界

- 所有长期保存的个人信息必须由用户主动提供或确认；9 项档案问题用户均可跳过，不得强迫
- 用户可以查看、修改、删除自己的所有工作台数据（profile.json / orders.csv / nutrition.csv / store-preferences.json / temporary-rules.json 及衍生报告）
- 不把用户完整订单数据上传到公开 GitHub 仓库或其他公开渠道
- 读取历史订单（order-list）前必须获得用户明确允许（profile.json 的 `allow_order_sync`）

## 真实性边界

- 不伪造菜单、价格、优惠、库存、门店或订单状态
- MCP 不可用时宁可停用功能，也不用示例数据冒充真实数据
- dashboard.html 等辅助视图只能展示已从 MCP 获取并保存的数据，不能伪造实时同步、优惠或下单功能；所有实时业务动作由 skill 调用 MCP 完成
- 手动补录订单必须标记 `data_source=manual`，不与 MCP 记录混淆

## 健康与营养边界

- 热量和营养数据仅供记录、趋势观察和点餐参考
- 不提供医疗诊断、减肥保证或专业营养建议
- 禁止输出"这样吃一定会变胖""再吃会得病"等绝对性结论
- 趋势报告使用"已知热量 / 估算热量 / 记录热量"等谨慎表述

## 高风险操作（全部需用户明确确认）

创建订单、取消订单、自动领取优惠券（auto-bind-coupons）、新增配送地址（delivery-create-address）、兑换积分商品（mall-create-order）、发起抽奖（draw-lottery）。

下单五步流程（缺一不可）：

1. 生成推荐方案，不下单
2. 用户表达采用意图后调用 calculate-price
3. 展示最终订单（门店/就餐方式/餐品/优惠/预计实付）并询问"确认创建订单吗？"
4. 仅当用户明确回复"确认下单""创建订单"等表达后调用 create-order
5. 订单成功后更新 orders.csv 并刷新工作台数据

用户取消/关闭支付后想对同一订单重新支付时，遵循微信支付相关技能中"重新支付需先确认订单"的流程（如适用）。
